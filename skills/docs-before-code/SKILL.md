# Docs Before Code — Document the Contract

If you cannot explain it, do not build it yet.

## Process
1. Write the usage example and the expected behavior.
2. Document parameters, return values, and error cases.
3. Get feedback on the docs before heavy implementation.
4. Keep the docs in sync with the code.
5. Treat outdated docs as a bug.

## Verification
- [ ] Usage example exists
- [ ] Error cases documented
- [ ] Docs match the implementation
