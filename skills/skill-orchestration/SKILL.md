# Skill Orchestration — Use the Right Skill

Do not invent a process when a skill already covers it.

## Routing
- Vague ask → requirements-interrogation
- Fuzzy idea → idea-refinement
- New work → spec-driven-development then task-planning
- Implementation → incremental-build + test-driven-development
- Bug → systematic-debugging
- Before merge → multi-axis-review
- Before deploy → ship-checklist

## Shared Rules
- Spec before code.
- Tests are proof.
- One slice at a time.
- Verify before declaring done.

## Verification
- [ ] Correct skill selected for the current work
- [ ] Shared rules still enforced
