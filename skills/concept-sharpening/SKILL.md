# Concept Sharpening
Offer alternatives only when they expose a meaningful trade-off.

## Process
1. Capture the problem, intended user, constraints, and available evidence.
2. Propose two or three distinct approaches when alternatives genuinely exist; do not manufacture options for a settled request.
3. Compare usefulness, implementation cost, uncertainty, and operational burden.
4. Recommend one direction and the smallest experiment that could disprove it.
5. Proceed when the user has chosen or delegated the choice. Ask only if the options imply materially different outcomes.

## Example
For search, compare improving database queries with a dedicated search index using required ranking, data volume, and update frequency. Do not introduce an index solely because it is fashionable.

## Stop conditions
Do not turn exploration into implementation outside the requested scope.

## Evidence
- [ ] Options solve the same stated problem.
- [ ] Recommendation names its trade-off and uncertainty.
- [ ] A concrete next experiment or acceptance criterion exists.
