# Spec-Driven Development — Spec Before Code

No implementation starts until the spec is reviewed and accepted.

## Required Spec Sections
- Objective (what and why)
- User stories / acceptance criteria
- Tech stack and versions
- Commands (build, test, lint, run)
- Project structure
- Code style and boundaries
- Testing strategy
- Out of scope
- Success criteria

## Process
1. Draft the full spec.
2. List open questions.
3. Require explicit user approval.
4. Save as SPEC.md in the repo root.
5. Only then allow planning or coding.

## Verification
- [ ] All required sections present
- [ ] Acceptance criteria are testable
- [ ] User explicitly approved
- [ ] SPEC.md committed
